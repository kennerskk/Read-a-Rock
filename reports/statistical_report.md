## 0. การออกแบบการทดลอง (Experimental Design)

| รายการ | ค่า |
|:---|:---|
| หน่วยวิเคราะห์ (unit of analysis) | **แมตช์** ไม่ใช่ตา |
| จำนวน replication ต่อคู่ | 30 แมตช์ |
| จำนวนตาต่อแมตช์ | 1000 ตา |
| seed ที่ใช้ | 0 ถึง 29 |
| การจับคู่ | Common Random Numbers (CRN) |
| ระดับนัยสำคัญ | alpha = 0.05 |
| การแก้ multiple comparisons | Holm-Bonferroni |

เหตุผลที่ใช้ *แมตช์* เป็นหน่วยวิเคราะห์: บอสเรียนรู้ระหว่างเกม (`learn()` ถูกเรียกทุกตา) ทำให้ผลแต่ละตาไม่เป็นอิสระต่อกัน การคำนวณ binomial confidence interval จาก 1000 ตาในแมตช์เดียวจะให้ช่วงความเชื่อมั่นที่แคบเกินความจริง จึงต้องรันหลายแมตช์อิสระแล้วคิดสถิติจากค่า R ของแต่ละแมตช์

ตัวชี้วัด: `R = (W + 0.5D)/N x 100` ซึ่งทำให้การเล่นสุ่มล้วนมีค่าคาดหวัง `E[R] = 50.0%` พอดี จึงใช้เป็นสมมติฐานหลัก (null hypothesis) ได้โดยตรง

### Sanity / Falsification check

ตามทฤษฎีเกม ไม่มีกลยุทธ์ใดเอาชนะผู้เล่นที่สุ่มสมบูรณ์ (Nash equilibrium 1/3) ได้ในระยะยาว ดังนั้นถ้าโมเดลใดชนะ persona นี้เกิน 50% อย่างมีนัยสำคัญ แปลว่าโค้ดมีบั๊กหรือมี data leakage

**ผ่าน** — ไม่มีโมเดลใดชนะผู้เล่นสุ่มได้เกิน 50% อย่างมีนัยสำคัญ ผลสอดคล้องกับทฤษฎีเกม ยืนยันว่าระบบจำลองไม่มี data leakage

## 3. จัดอันดับรวม: Friedman test + Nemenyi post-hoc

วิธีมาตรฐานสำหรับเทียบหลายโมเดลพร้อมกันหลายเงื่อนไข (Demšar, JMLR 2006) บล็อก = (persona × seed) รวม 120 บล็อก ทุกโมเดลเจอบล็อกเดียวกันทุกบล็อก

- **Friedman χ² = 285.536**, df = 7, **p = 7.402e-58**
- p < 0.05 จึงปฏิเสธ H₀: โมเดลทั้งหมดมีประสิทธิภาพ**ไม่เท่ากันจริง** สามารถทำ post-hoc ต่อได้
- **Critical Difference (CD) = 0.958** อันดับ

| รายการ | ค่า |
|:---|---:|
| SD ของผลต่างแบบจับคู่ (median) | 1.56 pp |
| n ที่ใช้จริง | 30 แมตช์ |
| ผลต่างเล็กสุดที่ตรวจจับได้ (MDE, power = 0.80) | 0.80 pp |
| n ที่ต้องใช้เพื่อตรวจจับผลต่าง 2.00 pp | 5 แมตช์ |

สูตร (paired, two-sided): `MDE = (z_(α/2) + z_β) × SD_diff / √n` โดย z_(α/2) + z_β = 2.802 ที่ alpha = 0.05, power = 0.80 ตัวเลขนี้ยืนยันว่า n ที่เลือกมาจากการคำนวณ ไม่ใช่การกำหนดตามใจ

### การทดสอบรายคู่

ใช้สองวิธีประกอบกัน: (ก) เทียบคะแนนรายfoldแบบจับคู่ และ (ข) **McNemar's test** บนผลทำนายรายตาในชุด validation เดียวกัน ซึ่ง Dietterich (1998) แนะนำให้ใช้เมื่อเทียบ classifier สองตัวบนข้อมูลชุดเดียว

| คู่เปรียบเทียบ | fold-wise test | p (Holm) | McNemar p (Holm) | b / c |
|:---|:---|---:|---:|---:|
| LogisticRegression (Softmax) vs RandomForest (Ensemble Trees) | Wilcoxon | 1.48e-01 | 2.29e-01 | 86 / 107 |
| LogisticRegression (Softmax) vs GradientBoosting (Histogram) | Wilcoxon | 1.57e-04 ✱ | 3.26e-02 ✱ | 87 / 125 |
| RandomForest (Ensemble Trees) vs GradientBoosting (Histogram) | Wilcoxon | 1.48e-01 | 2.29e-01 | 43 / 60 |

`b` = จำนวนตาที่โมเดลซ้ายทำนายถูกแต่ขวาผิด, `c` = ซ้ายผิดแต่ขวาถูก McNemar ทดสอบว่า b กับ c ต่างกันเกินความบังเอิญหรือไม่ (exact binomial test) | ✱ = มีนัยสำคัญหลังแก้ Holm

## 7. สรุปข้อสรุปที่อ้างได้ (Defensible Conclusions)

1. ประสิทธิภาพของโมเดลทั้ง 8 ตัว **แตกต่างกันอย่างมีนัยสำคัญ** (Friedman χ² = 285.54, p = 7.40e-58)
2. โมเดลที่ได้อันดับเฉลี่ยดีที่สุดคือ **Markov** (อันดับเฉลี่ย 2.971 จาก 8 โมเดล)
3. มี 18 คู่ (โมเดล × persona) จาก 32 คู่ ที่ชนะเหนือ baseline การสุ่มอย่างมีนัยสำคัญหลังแก้ Holm
4. ระบบผ่าน sanity check: ไม่มีโมเดลใดเอาชนะผู้เล่นสุ่มสมบูรณ์ได้ ตรงตามที่ทฤษฎีเกมทำนาย
5. ที่ n = 30 แมตช์ การทดลองนี้มี power 0.80 ในการตรวจจับผลต่าง ตั้งแต่ 0.80 pp ขึ้นไป
